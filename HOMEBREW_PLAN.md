# Homebrew packaging for mpz (macOS cask)

## Context

mpz builds a universal macOS DMG on every GitHub release (`.github/workflows/release-macos.yml` → `mac/portable_macos_qt6_host.sh`) but has no Homebrew presence. Linux gets OmniPackage/AUR/AppImage/Flatpak; Windows gets a QtIFW installer; macOS users must find the releases page, drag the app, then hand-run `xattr -dr com.apple.quarantine` because the build is ad-hoc signed only (`portable_macos_qt6_host.sh:50`).

Goal: `brew install --cask olegantonyan/mpz/mpz` installs a launchable app with no Gatekeeper dance, and every release bumps the cask automatically.

Decisions: **cask** shipping the prebuilt DMG (not a source formula); **own tap** `olegantonyan/homebrew-mpz`; Gatekeeper handled by a cask **`postflight`** quarantine strip; bumped by a **new CI workflow** in this repo pushing to the tap on `release: published`.

### Why not the official homebrew-cask tap

Two blockers, both verified, both out of scope here:

1. **Notarization is mandatory upstream.** `Cask::Audit#audit_signing` skips non-official taps (`audit.rb:504`) but always runs for homebrew/cask, and errors with "The homebrew/cask tap requires all casks to be signed and notarized by Apple" (`audit.rb:576-582`). The ad-hoc-signed DMG fails `codesign --verify -R=notarized`. The `postflight` quarantine strip can't come along either — Acceptable Casks forbids bypassing Gatekeeper. Fixing this needs a $99/yr Apple Developer account plus `notarytool`/`stapler` in `release-macos.yml`.
2. **Notability, as a self-submission.** mpz has 108 stars / 4 forks / 4 watchers (created 2019, so age is fine). A third-party submission needs 30 forks *or* 30 watchers *or* 75 stars → passes. A submission by the repo owner needs 90 / 90 / **225** → falls short by ~117 stars.

Revisit when a Developer ID exists. The tap is unaffected either way — same DMG, and it stays the place to point people at meanwhile.

## Verified constraints

Checked against a local Homebrew 6.0.12 install, not from memory:

- `depends_on macos: ">= :big_sur"` **raises `MethodDeprecatedError`** under `HOMEBREW_DEVELOPER` (which `brew audit`/`brew style` set). Use the bare symbol `depends_on macos: :big_sur` — it already means `>=`.
- `verified:` on the `url` is **mandatory**: url host `github.com` ≠ homepage host `mpz-player.org`, so `Cask::Audit#audit_missing_verified` errors without it. No scheme, trailing slash.
- **Do not** set `auto_updates true`. `app/update_check/updatechecker.cpp` only notifies, never replaces the bundle; `auto_updates` makes `brew upgrade` *skip* the cask.
- Flat `Casks/mpz.rb` is fine — `Tap#cask_files` globs `Casks/**/*.rb`; sharding is homebrew-cask-only.
- `postflight` has `appdir`, `staged_path` and `system_command` (`Cask::DSL::Base` delegators). No `sudo:` needed.
- Homebrew quarantines by default (`Cask::Installer`, `quarantine: true`) and `Quarantine.propagate` stamps **every file** in the bundle → the strip must be recursive.
- `brew install --cask olegantonyan/mpz/mpz` auto-taps *and* auto-trusts. A separate `brew trust` is only needed for the short-token flow.
- sha256 of the live 2.1.2 DMG: `125af2200fcffa1031c2a0954b92ebb3b35463582ea0e8bd4355955c9db8cb3f` (confirmed by download).

## 1. Tap repo — `olegantonyan/homebrew-mpz`

Do **not** use `brew tap-new`: it scaffolds `Formula/`, never `Casks/`, plus bottle-building workflows that are meaningless here.

```bash
mkdir -p ~/projects/homebrew-mpz/Casks && cd ~/projects/homebrew-mpz
git init -b main
# write Casks/mpz.rb, README.md, LICENSE
git add --all && git commit -m "mpz 2.1.2"
gh repo create olegantonyan/homebrew-mpz --public --source=. --remote=origin \
   --description "Homebrew cask for mpz music player" --push
```

Repo name must be `homebrew-mpz` — `Tap#initialize` hardcodes `@full_repository = "homebrew-#{@repository}"` (`tap.rb:299`) and `default_remote` builds the URL from that.

Reusing `olegantonyan/mpz` as the tap was considered and rejected. It only works via the two-argument `brew tap olegantonyan/mpz <URL>` form, so the fully-qualified `brew install --cask olegantonyan/mpz/mpz` — the form the README advertises — 404s. It also drags a ~30 MB clone (vendored taglib, yaml-cpp, cpptrace, libmpdclient, QHotkey) into `Library/Taps` on every `brew update`, and with no `Formula/` dir present `potential_formula_dirs` falls back to the repo root (`tap.rb:947`), so any root-level `.rb` added later would be parsed as a formula.

Contents: `Casks/mpz.rb` (below), `README.md` (install/upgrade/zap commands; note that the cask is generated by CI and fixes go to the template in the main repo), `LICENSE` (BSD-2-Clause, matching Homebrew/homebrew-cask — packaging metadata only; mpz itself stays GPL-3.0-or-later).

Optional `.github/workflows/ci.yml` on `macos-latest` running `brew style --cask Casks/mpz.rb` and `brew audit --cask --online --strict Casks/mpz.rb`. Pushes made with the PAT do trigger it.

### `Casks/mpz.rb`

```ruby
cask "mpz" do
  version "2.1.2"
  sha256 "125af2200fcffa1031c2a0954b92ebb3b35463582ea0e8bd4355955c9db8cb3f"

  url "https://github.com/olegantonyan/mpz/releases/download/#{version}/mpz-#{version}-macos-universal.dmg",
      verified: "github.com/olegantonyan/mpz/"
  name "mpz"
  name "mpz music player"
  desc "Music player for large local collections"
  homepage "https://mpz-player.org/"

  livecheck do
    url :url
    regex(/^v?(\d+(?:\.\d+)+)$/i)
    strategy :github_latest
  end

  depends_on macos: :big_sur

  app "mpz music player.app"

  # The DMG is ad-hoc signed only; without this Gatekeeper blocks first launch.
  postflight do
    system_command "/usr/bin/xattr",
                   args:         ["-d", "-r", "com.apple.quarantine", "#{appdir}/mpz music player.app"],
                   must_succeed: false,
                   print_stderr: false
  end

  uninstall quit: "org.mpz-player.mpz"

  zap trash: [
    "~/Library/Application Support/mpz",
    "~/Library/Caches/mpz",
    "~/Library/Preferences/mpz",
    "~/Library/Saved Application State/org.mpz-player.mpz.savedState",
  ]
end
```

Notes on the non-obvious bits:

- `must_succeed: false` — `--no-quarantine` installs never set the attribute, and `xattr -d` then exits non-zero.
- `uninstall quit:` — without it `brew upgrade --cask` swaps the bundle under a running mpz. Bundle id from `CMakeLists.txt:314`.
- `zap` paths — `app/main.cpp:91` sets `setApplicationName("mpz")` with no org, so Qt resolves to `~/Library/{Preferences,Caches,Application Support}/mpz` (used at `app/config/storage.cpp:36`, `app/diskcache.cpp:17`, `app/ipc/instance.cpp:29`, `app/main.cpp:104`). No `QSettings` anywhere, so there is no `.plist`. Array must stay alphabetical (`Cask::ArrayAlphabetization`).
- Anchored livecheck regex — Homebrew's unanchored default would pull `0.0.1` out of the legacy `mpz-0.0.1` tag. `strategy :github_latest` hits `/releases/latest` (one request) and can't return that tag anyway.
- Stanza grouping and blank lines follow `RuboCop::Cask::Constants::STANZA_GROUPS`; `brew style` enforces it.

## 2. CI — new files in the mpz repo

Mirrors the existing cross-repo publish pattern in `.github/release-aur-github-action.rb` + `.github/aur/*.erb`.

**`.github/homebrew/mpz.rb.erb`** — the cask above with two substitutions: `version "<%= version %>"` and `sha256 "<%= sha256 %>"`. Everything else copied verbatim; ERB uses `<% %>` so the literal `#{version}` / `#{appdir}` pass through untouched.

**`.github/release-homebrew-cask-github-action.rb`** (mode 0755) — same shape as the AUR script. Reads `CASK_VERSION`, `CASK_SHA256`, `CASK_TEMPLATE`, `TAP_REPO`, `HOMEBREW_TAP_TOKEN` from ENV (raise on missing); honours `DRY_RUN=1` (render + print, no clone/push, no token needed); renders with `ERB#result_with_hash`; then clone/commit/push:

```ruby
Dir.mktmpdir do |d|
  url = "https://x-access-token:#{tap_token}@github.com/#{tap_repo}.git"
  system("git", "clone", "--depth", "1", url, "#{d}/tap", exception: true)
  FileUtils.mkdir_p("#{d}/tap/Casks")
  File.write("#{d}/tap/Casks/mpz.rb", cask)
  Dir.chdir("#{d}/tap") do
    system("git", "config", "user.name", git_name, exception: true)
    system("git", "config", "user.email", git_email, exception: true)
    system("git", "add", "--all", exception: true)
    if `git status --porcelain`.strip.empty?
      puts "nothing to commit, #{tap_repo} already up to date"
    else
      system("git", "commit", "-m", commit_message, exception: true)
      system("git", "push", exception: true)
    end
  end
end
```

Use the **array form** of `system` (the AUR script interpolates shell strings) so the token can't be word-split into a trace. The `git status --porcelain` guard makes re-runs a clean no-op. Commit message follows BrewTestBot convention: `mpz 2.1.3` + blank line + the release URL.

**`.github/workflows/release-homebrew-cask.yml`** — triggers `workflow_dispatch` (input `release_tag`, required) + `release: [published]`; `runs-on: ubuntu-latest`; `timeout-minutes: 45`; `permissions: contents: read`; `concurrency: {group: release-homebrew-cask}`; `RELEASE_TAG: ${{ github.event.release.tag_name || github.event.inputs.release_tag }}` mirroring `release-macos.yml:34`.

Steps:
1. `actions/checkout@v6`
2. **Guard** — bail unless `RELEASE_TAG` matches `^[0-9]+\.[0-9]+\.[0-9]+$`.
3. **Wait for the DMG** (see below).
4. **Hash** — `gh release download` the asset, `sha256sum`, emit to `$GITHUB_OUTPUT`.
5. `ruby/setup-ruby@v1` with `ruby-version: 4.0` (matches `release-aur-package.yml:21`).
6. Run the script with `HOMEBREW_TAP_TOKEN`, `TAP_REPO=olegantonyan/homebrew-mpz`, `CASK_TEMPLATE`, `CASK_VERSION`, `CASK_SHA256`.

### The race, and how it's solved

`release-macos.yml` and this workflow both fire on `release: published`, but the cask job needs the DMG already on the release. Fix: **bounded poll**, 60 attempts × 30 s.

```bash
DMG="mpz-${RELEASE_TAG}-macos-universal.dmg"
for i in $(seq 1 60); do
  state=$(gh release view "$RELEASE_TAG" --repo "$GITHUB_REPOSITORY" --json assets \
            --jq ".assets[] | select(.name == \"$DMG\") | .state" 2>/dev/null || true)
  if [ "$state" = "uploaded" ]; then
    echo "name=$DMG" >> "$GITHUB_OUTPUT"; exit 0
  fi
  echo "attempt $i/60: state='${state:-missing}', sleeping 30s"
  sleep 30
done
echo "::error::'$DMG' never appeared on release '$RELEASE_TAG' after 30 minutes"; exit 1
```

Checking `state == "uploaded"` (not just "name is listed") closes a second race: GitHub registers an asset in `starter`/`uploading` state before the bytes land, and hashing it then yields a wrong sha256.

30 min gives ~4× headroom — the 2.1.2 macOS run took 7m14s. Public repo, so the idle wait is free.

Rejected alternatives: `workflow_run` chaining (the payload has no `release` object, and `release-macos.yml` also fires on plain master pushes, so the tag would have to be reverse-engineered from `head_branch`); a `gh workflow run` dispatch step appended to `release-macos.yml` (works, but couples the two and breaks if the DMG is ever uploaded by a manual re-run).

## 4. Verification

**Lint** (run against 2.1.2, since `--online` downloads the real asset):

```bash
cd ~/projects/homebrew-mpz
brew style --cask Casks/mpz.rb
brew audit --cask --new Casks/mpz.rb          # implies --strict --online
brew livecheck --cask --debug Casks/mpz.rb    # expect: mpz : 2.1.2 == 2.1.2
```

**Install from a local path** (no tap, no trust — `Trust.require_trusted_cask!` returns early for files outside `Library/Taps`):

```bash
brew install --cask ~/projects/homebrew-mpz/Casks/mpz.rb
```

**Confirm the postflight worked** — the recursive check is the one that matters, since `Quarantine.propagate` stamps every file:

```bash
find "/Applications/mpz music player.app" -exec xattr -p com.apple.quarantine {} \; 2>/dev/null   # no output
spctl --assess --type execute --verbose "/Applications/mpz music player.app"
open -a "mpz music player"    # must launch with no "unidentified developer" dialog
```

**Uninstall round-trip** — launch mpz first, then `brew uninstall --cask mpz` and confirm the `Quitting application 'org.mpz-player.mpz'` line; check config dirs survive; then `brew uninstall --cask --zap --force mpz` and confirm `~/Library/{Preferences,Caches,Application Support}/mpz` are gone.

**Dry-run the pipeline** before tagging:

```bash
DRY_RUN=1 CASK_VERSION=2.1.2 \
CASK_SHA256=125af2200fcffa1031c2a0954b92ebb3b35463582ea0e8bd4355955c9db8cb3f \
CASK_TEMPLATE=./.github/homebrew/mpz.rb.erb TAP_REPO=olegantonyan/homebrew-mpz \
./.github/release-homebrew-cask-github-action.rb
```

Output must be byte-identical to the hand-written `Casks/mpz.rb`.

**End-to-end, zero side effects** — once the workflow is on master, dispatch it against the *existing* 2.1.2 release. The poll returns on attempt 1 and the `git status --porcelain` guard makes the push a no-op:

```bash
gh workflow run release-homebrew-cask.yml -f release_tag=2.1.2 --repo olegantonyan/mpz
brew install --cask olegantonyan/mpz/mpz    # full tap+trust path
```
